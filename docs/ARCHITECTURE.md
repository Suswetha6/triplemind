# Architecture

## Components

| Component | What it is | Why it exists |
|---|---|---|
| **frontend** | React 18 + Vite bundle, served by unprivileged nginx | The UI, and the single public entry point. nginx also proxies `/api`, which is what keeps the browser on one origin. |
| **backend** | FastAPI (uvicorn, one worker per pod) | Proxies every Groq call so the user's API key never appears in a browser→provider request, and so there is one place to meter, log and trace provider traffic. |
| **Groq API** | External dependency | Whisper for transcription, Llama for suggestions and chat. Not operated by us; treated as unreliable. |

There is no database and no cache. Session state (transcript, suggestions,
chat) lives in the browser's memory; settings live in `localStorage`. That is
the single most important architectural fact about this system — it is why
both workloads are stateless Deployments, why no PersistentVolume exists, and
why a pod can be killed at any moment without losing user data.

## Request path

```
Browser
  │  https://<host>/
  ▼
Ingress (ingress-nginx)            proxy-buffering off, 300s read timeout
  │                                 — required or SSE chat arrives in one lump
  ▼
Service: triplemind-frontend  (ClusterIP :80 → :8080)
  │
  ▼
frontend pod — nginx
  ├── /                 → static bundle, SPA fallback to index.html
  ├── /healthz          → answered by nginx itself (never proxied)
  └── /api/*            → proxy_pass, buffering off
            │
            ▼
      Service: triplemind-backend  (ClusterIP :8000)
            │
            ▼
      backend pod — FastAPI
        middleware: CORS → TrustedHost → RequestContext → RateLimit → BodySize
        ├── /healthz /readyz /version /metrics
        └── /api/transcribe  /api/suggestions  /api/chat
                  │
                  ▼  Authorization: Bearer <the user's key, forwarded>
            api.groq.com
```

### Why the API is not a separate Ingress path

Routing `/api` at the Ingress to the backend Service would work, but it puts
the frontend/backend split in two places that must agree, and it makes the
browser's API origin a second host in some configurations — which means CORS,
which means another thing to get wrong. Proxying inside the frontend pod keeps
the browser on exactly one origin and lets the backend's CORS allowlist stay
empty.

## Failure boundaries

| Failure | Blast radius | Why |
|---|---|---|
| Groq is down or slow | Transcription and suggestions fail; the UI still loads, the transcript panel still shows prior chunks | `/healthz` never calls Groq, so pods are not restarted and are not pulled from the Service |
| Backend pod dies | Requests in flight on that pod fail; others unaffected | 2+ replicas, `maxUnavailable: 0`, readiness-gated rollout |
| Frontend pod dies | Static serving continues on the other replica | Separate Deployment from the backend — a backend outage never takes the UI offline |
| Bad release | Caught by readiness before old pods are retired | `maxSurge: 1, maxUnavailable: 0` + `helm --wait`; CD rolls back automatically on failed verification |
| Node drain | At most one pod of each component at a time | PodDisruptionBudget `minAvailable: 1` |
| Abusive client | Rejected at the pod with 429 | Sliding-window limiter, per pod (see DECISIONS.md for the honest limitation) |

## Signals

Every request gets an `X-Request-ID` — taken from the caller if supplied,
generated by nginx otherwise — which flows through nginx's access log, the
backend's access log, every application log line emitted while handling that
request, and (when tracing is on) the trace id. One id, four places.

- **Metrics** — `/metrics` on the backend: request rate/latency/in-flight by
  route, Groq call rate/latency/outcome by operation, rate-limit rejections,
  and `triplemind_build_info` carrying the running version.
- **Logs** — JSON on stdout from both tiers, same field names.
- **Traces** — OTLP/HTTP to Tempo, FastAPI and httpx instrumented, so a slow
  request shows whether the time was ours or Groq's.

## Environments

| | Local (Compose) | kind | Reference production |
|---|---|---|---|
| Config | `docker-compose.yml` + `.env` | `values-dev.yaml` | `values-prod.yaml` |
| Replicas | 1 each | 1 each | 3 each, HPA to 12 |
| Images | built locally | side-loaded, `pullPolicy: Never` | GHCR, pinned by digest |
| NetworkPolicy | n/a | off (kindnet does not enforce it) | on |
| Tracing | optional profile | on with monitoring installed | on, 10% sampled |
| TLS | no | no | cert-manager + Ingress TLS |

The three differ only in values. There is no second copy of a manifest
anywhere in the repository.
